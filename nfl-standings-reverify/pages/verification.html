How this re-verification was done

The point of a re-verification is that the checking code is independent of the code that produced the data. This workspace parses the stored verbatim capture of the official standings page with a parser that shares no code with nfl-desk/engine/parse_standings.py, re-derives the league identities, and compares the fresh read to the stored read field by field.

The independent parser

nfl-standings-reverify/engine/parse.py reads captures/standings_2026-11-19.md (the verbatim rendered text of the official page) and splits each table row on its cells. It shares no code with the parser that produced nfl-desk/data/standings_2026-11-19.json. The stored read's own parser is nfl-desk/engine/parse_standings.py.

The stored read's raw evidence is nfl-desk/evidence/reads/standings_2026-11-19.txt, sha256 8dfd710663f6c676285749db87d39568231aeb27a5086939661768163793d8c2. Both reads are of the same official page on the same day (2026-11-19), so agreement between them is a transcription check, not a new observation.

What this does not claim

This workspace verifies the standings transcription against the official page. It does not compute ROI, CLV, win rate, a leaderboard entry or a reward — there is no licensed or official price source, and no graded games. It publishes no market line, residual or "beats the close" value. Those remain blank with a reason on the Flagged page.
