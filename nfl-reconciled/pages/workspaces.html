Why there are this many

No rule ever said where work must land

Each session read the same brief, found the repository already contained a complete answer from a previous session, and — correctly — refused to overwrite it. So it built a new workspace beside it. That is how 31 honest workspaces accumulate, and it is the same reason 26 separate decision registers exist side by side.

The fix is not another workspace. It is a rule: one namespace is canonical, and a new session must land its work inside it or write to the owner instead. That rule is open item RR-01 on the decisions page.
