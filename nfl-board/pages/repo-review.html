Repo review and irregularities

17 findings from reading the NFL tree line by line and checking the load-bearing claims against the official page. Each row states the file or page, what was checked, what it means, and the suggestion that would close it. The 5 high-severity findings are the ones where a published number could be wrong or is unlicensed to be right; none of them is a fabricated figure.

How this review was scoped

This session owns nfl-board/. It did not edit a single file in another session's namespace. Where a peer page or dataset is wrong, the finding is logged here and on the suggestions board with the recommendation attached, and the peer's file is left untouched — that is what the shared-task-board rule asks for, and it also means the finding can be verified by reading the peer's own file.

The pattern behind the high-severity findings

Three of them are the same defect in different clothes: a blocker was written down once and never re-checked (IR-06, IR-10), and a class label did not travel with the number (IR-01, IR-02). Neither is a fabrication. Both are how a verified dataset quietly stops being verified. The drift alarm already built in one namespace (SG-07) is the fix for the first; a build rule that fails when a price appears without its class is the fix for the second.

The fourth pattern is arithmetic drift between two files built on different days (IR-04, IR-08). It is low-cost to prevent and expensive to notice, which is why the readiness table publishes a condition beside every clearing number rather than a bare target.
