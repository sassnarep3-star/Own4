09 / Repository audit

This repository was not built for rental law.

The existing root project is an unrelated NBA research/dashboard site. The rental review is deliberately served from its own directory and does not replace or modify the prior work.

PRE-EXISTING PROJECTS

Both the NBA site and peer rental work are preserved

  • The root index.html, generated NBA pages, NBA documentation, and existing canonical-site validation workflow belong to a separate project.
  • After this branch was created, main advanced with peer-owned rental dashboards, including the existing rental-sf/index.html, plus separate rent-sf/, rental/, and rental-own4/ workspaces. None was overwritten.
  • No NBA HTML, generator, documentation, workflow, peer dashboard, or root Pages configuration was changed for this deliverable.
ISOLATED DELIVERABLE

Nested to avoid a namespace collision

  • This expanded, 10-page legal/source review lives under rental-sf/counsel-review/; the peer-owned rental-sf/ landing page remains intact.
  • The site is static HTML/CSS with no backend, analytics, external JavaScript, or private tenant data.
  • Pages navigation and assets use relative paths so the nested subdirectory works under the repository’s GitHub Pages URL.

Pages configuration checked before publication

Existing Pages uses the main-branch root.

The GitHub Pages API reported the repository’s public site using the legacy Pages build, source branch main, path /, and HTTPS. Under that configuration, this expanded review will be served at its nested repository subpath after merge and rebuild:

https://sassnarep3-star.github.io/Own4/rental-sf/counsel-review/

The existing peer landing page remains at /rental-sf/; the root remains the pre-existing NBA site. No Pages settings, peer site, or existing workflow changes were required. After merge, confirm the deployment status and open the URL in a browser; a successful repository build alone does not prove that the nested Pages URL is live.

Integrity controls

Scope and privacy checks

  • Only generic unit labels are used; tenant names and initials are omitted from public files.
  • Owner-supplied amounts/dates are labeled unverified and separated from legal conclusions.
  • Every data-table row links to an official government source for the legal rule it discusses; the site says expressly when that source cannot authenticate private tenancy facts.
  • The build verifier checks internal links, registered official-source links, HTTPS, and a source link in every table row.
